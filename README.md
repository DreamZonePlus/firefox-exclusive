# متصفح Firefox بجلسة حصرية "واحدة في الوقت" بدون كلمة سر

غلاف حول حاوية [jlesage/docker-firefox](https://github.com/jlesage/docker-firefox) يضيف ميزة غير موجودة في الحاوية الأصلية:

- **الدخول بدون كلمة سر** (افتراضياً)، مع إمكانية تفعيل اسم مستخدم وكلمة سر وقت الحاجة.
- **أول من يفتح الصفحة يحجز المتصفح لنفسه** ويُحجب الدخول على أي شخص آخر.
- يرى المحجوبون صفحة تحمل العبارة «المتصفح قيد الاستخدام من قبل مستخدم آخر» فقط،
  وتُعِيد المحاولة تلقائياً كل بضع ثوانٍ، ويدخلون تلقائياً بمجرد تحرر الدور.
- الجلسة محكومة بحد أقصى للمدة، ويُحرَّر الدور أيضاً بعد مغادرة المستخدم بفترة سماح قصيرة (فرصة ليعود).
- **عدد المستخدمين المتزامنين قابل للضبط** (`MAX_USERS`): الافتراضي 1 (واحد في الوقت)،
  ويمكن السماح لعدة مستخدمين معاً بتحديد العدد.

## البنية

```
المستخدم ──► gateway (بوابة الحجز) ──► firefox (حاوية jlesage/firefox)
              المنفذ 8080               المنفذ الداخلي 5800 (غير منشور)
```

البوابة تعطي أول زائر كوكي جلسة عشوائي (بدون كلمة سر). أي طلب أو اتصال WebSocket من
صاحب الكوكي يُمرَّر إلى الحاوية، ومن غيره يستقبل صفحة "مشغول".

## الإعدادات (متغيرات البيئة لخدمة gateway)

جميع هذه المتغيرات موجودة في `docker-compose.yml` وقابلة للتعديل من Coolify دون
تعديل المستودع (انظر الملاحظة أسفل الجدول).

### إعدادات الحجز والتوقيت

| المتغير | الافتراضي | الوظيفة |
| --- | --- | --- |
| `MAX_USERS` | `1` | عدد المستخدمين المتزامنين المسموح لهم بالدخول معاً. `1` = وضع "واحد في الوقت" الحصري؛ عند رفعها يُسمح لهذا العدد فقط، ويرى من بعدهم صفحة الحجب. |
| `LOCK_MAX_MINUTES` | `60` | الحد الأقصى لجلسة المستخدم الواحد بالدقائق (تُقبل كسوراً مثل `0.5`). بعده يُطرد ويُحرَّر الدور لغيره، ويُمنع هو من الدخول فوراً لفترة تساوي مهلة السماح. |
| `LOCK_GRACE_SECONDS` | `120` | بعد أن يغلق المستخدم الصفحة/ينقطع اتصاله، كم ثانية يبقى الدور محجوزاً له قبل أن يُتاح لغيره (فرصة ليعود). |
| `BUSY_RETRY_SECONDS` | `10` | كل كم ثانية تُعِيد صفحة "مشغول" المحاولة تلقائياً. |

### إعدادات الدخول (معطّلة افتراضياً)

| المتغير | الافتراضي | الوظيفة |
| --- | --- | --- |
| `AUTH_USERNAME` | (فارغ) | اسم المستخدم لتسجيل الدخول. **معطّل افتراضياً**؛ يُفعَّل فقط عند تعبئته مع `AUTH_PASSWORD` معاً. |
| `AUTH_PASSWORD` | (فارغ) | كلمة السر لتسجيل الدخول. عند تعبئة القيمتين معاً تظهر صفحة دخول عربية قبل الوصول للمتصفح، ويعمل نظام الأدوار بعدها كالمعتاد. |

### إعدادات إدارية وتقنية

| المتغير | الافتراضي | الوظيفة |
| --- | --- | --- |
| `ADMIN_KEY` | قيمة مولّدة | مفتاح تحرير طوارئ لكل الأدوار دون إعادة نشر: `/__gateway/status?release=<المفتاح>`. **غيّره لقيمة خاصة بك.** |
| `BACKEND_HOST` | `firefox` | اسم خدمة الحاوية الخلفية (نادراً ما يُغيَّر). |
| `BACKEND_PORT` | `5800` | منفذ الحاوية الخلفية الداخلي. |
| `LISTEN_PORT` | `8080` | منفذ استماع البوابة (نفسه الذي يُربط به الدومين في Coolify). |

> **عبر Coolify**: هذه المتغيرات تظهر بعد النشر في قسم **Environment Variables ← Production**
> (بفضل صيغة `${VAR:-الافتراضي}` في `docker-compose.yml`) — عدّل قيمها من هناك وأعد النشر،
> دون الحاجة لتعديل المستودع. ترك الحقل فارغاً أو حذفه يعيد الافتراضي المذكور في الجدول.
> **تنبيه**: المتغيرات تُقرأ عند إقلاع الحاوية — أي تعديل يحتاج Redeploy ليسري.

### سيناريوهات شائعة

- **"الأول يستخدم حتى يخرج"** (الافتراضي): اترك الإعدادات، أو ارفع `LOCK_MAX_MINUTES` (مثلاً `480`) وخفّض `LOCK_GRACE_SECONDS` (مثلاً `60`).
- **"فترات ثابتة"** (مثلاً كل مستخدم 30 دقيقة كاملة حتى لو خرج مبكراً):
  `LOCK_MAX_MINUTES=0.5` و `LOCK_GRACE_SECONDS=1800` (أي أسبقها مساوية للمدة القصوى أو أكبر).
- **"حجب فوري بعد الخروج"**: `LOCK_GRACE_SECONDS=5` مع أي قيمة للحد الأقصى.
- **"عدة مستخدمين معاً"**: `MAX_USERS=3` مثلاً — يُسمح لثلاثة جلسات متزامنة فقط، ويرى الرابع صفحة الحجب.
- **"حماية بكلمة سر"**: عبّئ `AUTH_USERNAME` و`AUTH_PASSWORD` معاً فتظهر صفحة تسجيل دخول
  قبل الوصول للمتصفح (بدونها يبقى الدخول مفتوحاً للجميع كما هو الافتراضي).

## المزايا الجديدة بالتفصيل

### تسجيل الدخول (AUTH_USERNAME / AUTH_PASSWORD)

- **معطّل افتراضياً**: القيمتان فارغتان في `docker-compose.yml` — الدخول مباشر بدون كلمة سر.
- **التفعيل**: عبّئ القيمتين معاً في Coolify (Environment Variables ← Production) ثم أعد النشر.
  تعبئة واحدة فقط دون الأخرى لا تُفعّل شيئاً (يُشترط اكتمال الاثنتين).
- عند التفعيل: كل زائر يرى صفحة دخول عربية (اسم مستخدم + كلمة سر) قبل أي شيء آخر،
  ويحصل بعد نجاح الدخول على كوكي مصادقة صالح لـ 30 يوماً. المقارنة تتم بزمن ثابت
  (timing-safe) لمقاومة هجمات قياس الزمن.
- **تسجيل الخروج**: `/__gateway/logout` — يمحو كوكي المصادقة **و** يحرر دور صاحبه فوراً
  (لا ينتظر مهلة السماح)، فيتاح مكانه للمستخدم التالي مباشرة.
- المصادقة مستقلة عن نظام الأدوار: كل مستخدم يسجل الدخول بنفس الحساب يعتبر مستخدماً
  منفصلاً بجلسة ودور خاصين.

### عدد المستخدمين المتزامنين (MAX_USERS)

- `MAX_USERS=1` (الافتراضي): الوضع الحصري — شخص واحد في المتصفح كله.
- `MAX_USERS=N` (N أكبر من 1): يُسمح لعدد N من الجلسات المستقلة بالدخول معاً؛
  كل جلسة لها كوكي مالك ودور خاص بها (مدة الجلسة ومهلة السماح تُطبقان على كل دور
  بشكل مستقل). من يصل بعد اكتمال العدد يرى صفحة الحجب حتى يتحرر أي دور.
- تغيير القيمة لا يؤثر على الجلسات القائمة — يسري على الطلبات الجديدة فقط.

### دورة حياة الدور (كيف يُحرَّر الحجز)

1. **الحجز**: أول زائر (أو صاحب الدور السابق) يفتح الصفحة يلتقط دوراً فوراً.
2. **البقاء**: طالما لدى المالك طلب HTTP نشط أو اتصال WebSocket حي — يبقى الدور محجوزاً له.
   البوابة تكتشف انقطاع WebSocket فور حدوثه (حتى إن لم ترد الخلفية بإغلاق الاتجاه المقابل).
3. **مهلة السماح** (`LOCK_GRACE_SECONDS`): عند مغادرة المالك (إغلاق الصفحة/انقطاع الشبكة)
   يبدأ عداد؛ إن عاد خلاله يستعيد دوره فوراً، وإلا يُحرَّر الدور ويستلمه أول منتظر.
4. **الحد الأقصى** (`LOCK_MAX_MINUTES`): مهما كان نشاط المالك، عند بلوغ المدة يُطرد ويُحرَّر
   دوره، ويُمنع هو من استعادة الدور لفترة تساوي مهلة السماح (كي لا يخطف الدور مجدداً فور طرده).

### نقاط نهاية البوابة

| المسار | الوصف |
| --- | --- |
| `/` (وأي مسار آخر) | الوكيل إلى حاوية firefox — أو صفحة الحجب إن لم يتوفر دور. |
| `/__gateway/status` | JSON عام: الحالة، عدد المستخدمين الحالي/الأقصى، تفعيل المصادقة، الوقت المتبقي، عدد الاتصالات النشطة. |
| `/__gateway/status?release=<ADMIN_KEY>` | تحرير كل الأدوار فوراً (طوارئ). |
| `/__gateway/login` | صفحة/نموذج تسجيل الدخول (يظهر فقط عند تفعيل المصادقة). |
| `/__gateway/logout` | تسجيل الخروج: تحرير الدور ومحو كوكي المصادقة. |

حقول `/__gateway/status` المهمة: `users` (الجلسات الحالية)، `maxUsers`، `authEnabled`،
`minutesLeft` (أقرب تحرر متوقع)، `activeSockets` (اتصالات WebSocket الحية — إن كان
`locked: true` مع `activeSockets: 0` فهذا يعني أن الدور في فترة السماح).

## التشغيل

### Docker عادي

```bash
cd firefox-exclusive
docker compose up -d --build
```

ثم افتح: `http://<عنوان-الخادم>:8080` (أو المنفذ الذي عيّنته).

### عبر Coolify

1. انقل هذا المجلد إلى مستودع Git خاص (أو استخدمه من مكانه).
2. في Coolify أنشئ مشروعاً جديداً من نوع **Docker Compose** واربطه بالمستودع.
3. **مهم جداً — ربط الدومين:** عند النشر سيظهر أكثر من خدمة (firefox + gateway).
   الدومين يجب أن يُربط **بخدمة `gateway` فقط** على المنفذ **8080**:
   - ادخل على خدمة gateway → قسم ** Domains** → أضف الدومين مع تحديد المنفذ 8080.
   - تأكد أن خدمة `firefox` **ليس عليها أي دومين ولا منفذ منشور**.
   - إذا رُبط الدومين بخدمة firefox فسيدخل الجميع معاً بلا أي حجز (هذا الخطأ الشائع الأول).
4. يتكفل Coolify/Traefik بـ HTTPS وتمرير WebSocket تلقائياً.

## التحقق من أن المرور يمر عبر البوابة

بعد النشر، تحقق فوراً قبل تجربة المستخدمين:

```bash
# 1) حالة البوابة مباشرة (نقطة نهاية عامة):
curl -s https://دومينك.dev/__gateway/status
# متوقع: {"gateway":"firefox-exclusive","status":"free",...}

# 2) ترويسة التعريف على أي استجابة:
curl -sI https://دومينك.dev/ | grep -i x-fx-gateway
# متوقع: x-fx-gateway: 1   ← وجودها يعني أن المرور عبر البوابة.
# غيابها يعني أن الدومين متصل بحاوية firefox مباشرة — راجع ربط الدومين.

# 3) محاكاة مستخدمين اثنين (جلسات منفصلة):
curl -s -o NUL -w "%{http_code}\n" -c /tmp/c1 https://دومينك.dev/   # متوقع: 200
curl -s -o NUL -w "%{http_code}\n" -c /tmp/c2 https://دومينك.dev/   # متوقع: 503
```

نقطة النهاية `/__gateway/status` تُظهر أيضاً: هل الدور محجوز، المتبقي من الجلسة بالدقائق،
عدد الاتصالات النشطة، وقيم الإعدادات — مفيدة للمراقبة والتشخيص.

### تحرير القفل يدوياً (طوارئ)

إذا علق الدور محجوزاً لسبب ما، يمكن تحريره فوراً دون إعادة نشر عبر مفتاح `ADMIN_KEY`
(معرّف في `docker-compose.yml` — غيّره لقيمة خاصة بك):

```bash
curl -s "https://دومينك.dev/__gateway/status?release=المفتاح-هنا"
```

## استكشاف الأخطاء

### صفحة noVNC تُظهر "Reconnecting..."

- **السبب الأشهر**: الدور كان محجوزاً لحظة اتصال WebSocket (يرفض بـ 403 فيعيد المحاولة)،
  أو الصفحة محمّلة من ذاكرة المتصفح قبل ربط الدومين بالبوابة (بلا كوكي مالك).
- **الحل 1**: تحديث قسري للصفحة — `Ctrl + Shift + R`.
- **الحل 2**: تحقق من الحالة: `curl -s https://دومينك.dev/__gateway/status` — إن كان
  `locked: true` مع `activeSockets: 0` فالدور معلّق؛ حرّره بمفتاح `ADMIN_KEY` (أعلاه).
- البوابة تشفى هذه الحالة ذاتياً: بمجرد تحرر الدور، تُعِيد noVNC الاتصال تلقائياً وتلتقط الدور.

### لماذا لا يعلق الدور عند الزوار العابرين؟

الحجز يتحرر تلقائياً بعد `LOCK_GRACE_SECONDS` من آخر نشاط للمالك (طلب HTTP أو اتصال
WebSocket). أي زائر HTTP عادي (بوت، فاحص، أو curl) لا يفتح WebSocket لا يستطيع حجز
الدور أكثر من مهلة السماح — والاستخدام الحقيقي يعني اتصال WebSocket حياً (تحافظ عليه
واجهة noVNC طوال الجلسة).

## ملاحظات أمنية

- لا تنشر منافذ حاوية `firefox` (5800/5900) — وإلا يُتجاوَز نظام الحجز بالكامل.
- ملف `docker-compose.yml` يعطّل VNC داخلياً (`VNC_LISTENING_PORT=-1`) لهذا السبب.
- استخدم HTTPS عبر الدومين في Coolify؛ بعض مزايا الواجهة (مزامنة الحافظة، الإشعارات، التثبيت كتطبيق) تعمل فقط في سياق آمن.
- بما أن الدخول بلا كلمة سر افتراضياً، فإن **أول طلب يصل** هو من يحجز الدور — أي أن برامج المسح الآلي قد تحجز الدور مؤقتاً إذا وصلت إلى العنوان. المهلة القصيرة بعد المغادرة تجعل الأثر محدوداً؛ ولتقليله استخدم دوميناً غير معلن.
- للحماية الكاملة من الزوار غير المرغوب فيهم: فعّل `AUTH_USERNAME` و`AUTH_PASSWORD`
  (انظر قسم "تسجيل الدخول" أعلاه) — عندها لا يصل أحد للمتصفح قبل تسجيل الدخول.
